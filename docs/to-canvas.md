# 給 Gemini Pro / Canva 的前端介面設計提示詞

用途：

- 這是一份臨時提示詞檔，專門用來交給 Gemini Pro 或 Canva AI 協助做前端網頁介面設計
- 重點是產出介面視覺、版面、元件與畫面概念，不是寫前端程式碼

## 主提示詞

```text
你是一位擅長資訊型產品、學習平台與知識型網站的資深產品設計師。請幫我設計一個前端網頁介面，這個網站的用途是幫助使用者學習、閱讀、快速複習，並在實作網站開發時做逐項檢查。

這個產品不是一般部落格，也不是 generic SaaS dashboard，而是一個「學習型知識工作台」。

網站內容有三種主要模式：
1. 完整指南閱讀模式
2. 速讀大綱模式
3. 實作檢查清單模式

內容主題是：標準且符合業界實用的網站開發流程，從 MVP、UX/UI、技術架構、AI 協作、測試、資安、效能、SEO、CI/CD 到規模化。

請根據以下方向設計高品質前端介面。

一、產品目標
- 讓使用者快速理解整體網站開發流程
- 讓使用者可以在完整閱讀、快速複習、實作檢查之間自由切換
- 讓使用者在長文閱讀時不迷路
- 讓使用者在實作時可以清楚看到進度與待辦

二、主要使用者
- 自學者：想系統學會網站開發流程
- 實作者：正在規劃或製作網站
- 團隊協作者：想快速對齊流程與標準

三、請設計的頁面
1. 首頁 / 學習儀表板
2. 完整指南閱讀頁
3. 速讀大綱頁
4. 實作檢查清單頁
5. 比較模式頁（左邊閱讀內容，右邊 checklist）
6. 手機版首頁與手機版 checklist 頁

四、首頁必須有
- 清楚標題與副標
- 三個模式入口卡片
- 整體學習流程地圖
- 繼續上次進度區塊
- 推薦閱讀路線

五、完整指南閱讀頁必須有
- 左側章節導航
- 中間高品質長文閱讀區
- 右側閱讀進度、章內目錄、快捷入口
- 可以快速切到速讀版與 checklist

六、速讀大綱頁必須有
- 高掃讀性卡片
- 每節重點摘要
- 可快速跳去完整版

七、實作清單頁必須有
- 分組 checklist
- 勾選狀態與進度條
- 已完成 / 未完成篩選
- 每組可對應回完整內容

八、比較模式頁必須有
- 左右對照版面
- 左側可放全文或大綱
- 右側放 checklist
- 有同步對照感，不是單純兩欄拼接

九、視覺方向
- 走 Editorial Study Desk + Workflow Board 的感覺
- 像一本精心編排的學習手冊 + 一個實用工作台
- 專業、溫暖、成熟、清楚
- 不要做成 generic SaaS dashboard
- 不要紫色主題
- 不要玻璃擬態
- 不要只有首頁漂亮、內容頁卻很普通

十、色彩方向
- 暖米色背景
- 深墨藍灰主文字
- 青綠色作為主強調色
- 陶土橘色作為次強調色
- 整體要安定、可讀、耐看

十一、字體方向
- 標題偏編輯感、有知識手冊感
- 內文偏高可讀性、適合長時間閱讀
- 可以使用 Noto Serif TC + Noto Sans TC 這類搭配

十二、版面要求
- 桌機版可用三欄：左導航 / 中內容 / 右工具
- 平板版做收合與重排
- 手機版不是縮小桌機，而是重新組織資訊

十三、元件與細節
- 模式切換器
- 流程地圖
- 章節導航
- 進度條 / 進度環
- checklist 卡片
- 摘要重點卡
- callout 區塊
- 搜尋或 command bar 的概念

十四、互動與回饋
- 模式切換需有 200-300ms 的平滑過渡動畫
- Checklist 勾選時有微小確認動畫（如打勾描繪或輕微縮放）
- 長文閱讀頁需有「返回頂部」浮動按鈕，滾動超過一屏後顯示
- 所有可點擊元件需有 hover 與 active 狀態的視覺區分
- 進度達成時有輕量視覺回饋（如進度環脈動或階段徽章亮起）
- 閱讀位置記憶與恢復提示

十五、無障礙要求
- 色彩對比度符合 WCAG AA 標準（4.5:1 以上）
- 支援鍵盤完整操作（Tab 導航、Enter/Space 啟動）
- 圖示需搭配文字標籤或 aria-label
- 進度指示不僅依賴顏色（同時使用圖示或文字）
- 焦點指示器清楚但不突兀（避免預設瀏覽器藍框，使用品牌色 outline）

十六、邊界狀態設計
- 首次使用：首頁顯示「開始學習」引導卡，提示選擇第一個模式
- 無進度時：「繼續上次進度」區塊顯示探索建議而非空白
- Checklist 全完成：顯示階段完成徽章與下一階段入口
- 載入中：使用骨架屏（skeleton screen）而非 spinner，保持版面穩定感
- 搜尋無結果：Command bar 顯示友善的 empty state 與建議關鍵字

十七、請輸出內容
- 整體視覺方向說明
- 首頁 wireframe / layout concept
- 閱讀頁 wireframe / layout concept
- checklist 頁 wireframe / layout concept
- compare 頁 wireframe / layout concept
- 手機版重排建議
- 顏色、字體、間距、元件風格建議
- 若可以，請用表格列出每個頁面的區塊與用途

十八、請避免
- 模板感
- 浮誇動效
- 過多漂浮卡片
- 紫色漸層
- 單純白底黑字 markdown 頁
- 把這個產品做得像企業後台

十九、你設計出來的結果，應該讓人感覺這是一個：
「願意反覆回來使用的學習型知識工作台，而不是一次性閱讀頁」
```

## 精簡版提示詞

適合你想快速丟給 Gemini Pro / Canva 先出第一版概念圖時使用。

```text
請幫我設計一個「學習型知識工作台」網站介面，主題是網站開發流程學習指南。

這個網站不是部落格，也不是 SaaS dashboard，而是幫助使用者：
- 深度閱讀完整指南
- 快速看速讀大綱
- 在實作時勾選 checklist

請設計以下畫面：
1. 首頁 / 學習儀表板
2. 完整指南閱讀頁
3. 速讀大綱頁
4. 實作清單頁
5. 比較模式頁
6. 手機版首頁與手機版 checklist 頁

風格方向：
- Editorial Study Desk + Workflow Board
- 專業、溫暖、成熟、清楚
- 暖米色背景、深色文字、青綠主色、陶土橘輔助
- 不要紫色主題
- 不要 generic dashboard
- 不要玻璃擬態

關鍵識別：讓人一眼記住這是「學習手冊」而非一般文件或企業後台

請讓介面重點放在：
- 長文閱讀不迷路
- 進度感
- 模式切換
- checklist 可操作性
- 桌機與手機都好用
```

## 補充要求

如果 Gemini Pro / Canva 支援更進一步輸出，請追加要求：

- 每個頁面都給一版桌機版與手機版概念
- 先出灰階 wireframe，再出高保真風格版
- 提供 1 套主視覺方向與 1 套保守備選方向
- 幫每個頁面標注區塊名稱與用途
- 手機版資訊優先順序：模式切換入口 → 主要內容 → 懸浮進度 → 導航抽屜

## 使用建議

建議流程：

1. 先丟「精簡版提示詞」拿第一版概念
2. 再丟「主提示詞」要求完整頁面與視覺系統
3. 最後拿結果對照 [design.md](./design.md) 做篩選與修正
